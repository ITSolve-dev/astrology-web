# Модель слоёв

Приложение организовано в четыре слоя с жёсткими границами ответственности.

```text
┌─────────────────────────────┐
│         App Layer           │  ← компонует всё приложение
├─────────────────────────────┤
│        Pages Layer          │  ← страницы, сборка фич для маршрутов
├─────────────────────────────┤
│       Feature Layer         │  ← бизнес-логика и UI фич
├─────────────────────────────┤
│       Shared Layer          │  ← переиспользуемые примитивы
└─────────────────────────────┘
```

**App** (`src/app/`) — инициализация, глобальные провайдеры (Router, Theme, ErrorBoundary). Единственный слой, который компонует фичи. Не содержит бизнес-логики.

**Pages** (`src/pages/`) — тонкий слой. Собирает фичи и виджеты для конкретного маршрута. Только импорты и лэйаут.

**Features** (`src/features/`) — самодостаточные бизнес-фичи. Каждая фича — вертикальный срез от UI до сетевого запроса.

**Shared** (`src/shared/`) — переиспользуемые компоненты, хуки, утилиты. Не знает о фичах и приложении.

## Вспомогательные слои (вводятся только при явной необходимости)

**Entities** (`src/entities/`) — доменные объекты, нужные нескольким фичам. Не содержат UI.

**Widgets** (`src/widgets/`) — составные UI-блоки из нескольких фич (Header, Sidebar).

## Внутренняя структура фичи

```text
features/
└── <feature-name>/
    ├── ui/           # React-компоненты, только презентация
    ├── model/        # Reatom-атомы, сервис, производные состояния
    ├── api/          # функции запросов к бэкенду
    ├── types.ts      # TypeScript-типы фичи
    └── index.ts      # публичное API — единственная точка входа
```

Обязательный файл внутри `model/` — `<feature-name>.service.ts`. Это единственная точка входа для взаимодействия с фичей снаружи.
